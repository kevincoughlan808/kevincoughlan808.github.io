Another solid week — pushed through Days 54–58 of the 100 Days of Code challenge. Finished up concurrency and then shifted into practical tooling stuff.

## What I built

Day 54 picked up where last week left off — `std::async`, futures, and promises. Async tasks felt straightforward after the thread pool groundwork, and promises clicked once I thought of them as one-shot signalling channels. Day 55 was the big one: a thread pool with a work queue and N worker threads. That pulled together everything from the concurrency stretch — threads, mutexes, condition variables, all of it.

Day 56 covered atomic operations — built a lock-free counter and dug into memory ordering. Then Days 57–58 pivoted into practical I/O. Day 57 was JSON parsing with nlohmann/json, reading and writing structured data. Day 58 wrapped up with argument parsing — first manually walking `argv`, then using the CLI11 library.

## What I learned

- The thread pool felt like the concurrency equivalent of the linked list milestone. All the individual pieces made sense in isolation, but wiring them together into something that actually dispatches work was where the understanding solidified.
- Memory ordering on the atomics day was humbling. `memory_order_relaxed` vs `memory_order_seq_cst` is one of those things where you can read the docs five times and still not be sure you've got it. I got it compiling and passing tests but I wouldn't say it's fully intuitive yet.
- nlohmann/json is shockingly pleasant to use. After all the template verbosity, a library that just lets you do `json["key"] = value` feels like cheating.

## Next up

- Probably heading into build systems and project structure — CMake is long overdue.
- Want to build a milestone project that combines the thread pool with file I/O — maybe a parallel file processor or something similar.
