Solid week — pushed through Days 50–53 of the 100 Days of Code challenge. Started with a milestone project and then dove into concurrency.

## What I built

Day 50 was the Phase 5 milestone: a BFS maze solver that reads a maze from a file and prints the shortest path. Good way to tie together file I/O and graph algorithms from the last few weeks into something visual and satisfying.

Then Days 51–53 shifted into multithreading. Day 51 covered `std::thread` basics — spawning threads, `join`, `detach`, `hardware_concurrency`. Day 52 was mutexes and `lock_guard` — wrote a deliberate data race, watched the output go haywire, then fixed it. Day 53 built on that with condition variables and a producer-consumer pattern.

## What I learned

- The maze solver was a nice confidence check. Two weeks ago I was implementing BFS for the first time in C++ — now I could wire it up with file I/O and actually solve something without much friction.
- Deliberately writing a data race on Day 52 gave me the same feeling as the AddressSanitizer day back in the memory management stretch. Seeing corrupted output from unsynchronized threads makes the problem real in a way that reading about it never does.
- Producer-consumer with condition variables is fiddly. The spurious wakeup thing sounds like paranoia until you read enough about why the while-loop check actually matters.

## Next up

- More concurrency — `std::async`, futures, and promises are probably next.
- Want to build something that actually benefits from parallelism, not just toy demos.
