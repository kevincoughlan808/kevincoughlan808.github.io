Solid week — pushed through Days 85–87 of the 100 Days of Code challenge. Shifted from design patterns into ECS and testing.

## What I built

Day 85 was a minimal Entity Component System — entities, Position and Velocity components, and a MovementSystem that iterates over entities with both. After weeks of design patterns this felt like the natural next step — ECS is basically patterns all the way down. Day 86 was Google Test setup using CMake's FetchContent, plus first unit tests. More infrastructure than code but getting a test framework wired up properly matters. Day 87 built on that with real tests — unit tests for the Counter commands from the Command pattern work and tests for the EventEmitter from the Observer work. Also added a gitignore to stop build directories from cluttering the repo, which was overdue.

## What I learned

- ECS clicked faster than I expected, probably because the pattern work leading up to it laid the groundwork. Components are just data, systems are just behavior, entities are just IDs. Simple in theory, simple in practice once you've internalized the separation.
- FetchContent for pulling in Google Test is clean — no manual downloads, no submodules, just a few lines in CMakeLists.txt. Should have set up testing infrastructure earlier in the challenge.
- Writing tests for the Command undo stack and the EventEmitter retroactively was a good exercise. Both had subtle edge cases I hadn't thought about when I first wrote them.
