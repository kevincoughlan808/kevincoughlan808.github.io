Solid week — pushed through Days 63–66 of the 100 Days of Code challenge. Shifted from tooling into performance and low-level optimization territory.

## What I built

Day 63 picked up the build system thread from the CMake work — static and dynamic libraries, linking, and runtime dependencies. Day 64 was profiling with `<chrono>` — timed O(n), O(n log n), and O(n²) functions and watched the curves diverge as input scaled up. Big O on a whiteboard is one thing; watching your O(n²) function fall off a cliff at n=100000 is another.

Day 65 was cache-friendly data layout — benchmarked Array of Structs vs Struct of Arrays and saw the SoA version pull ahead on tight loops. Day 66 got into SIMD territory — auto-vectorization with `-O2` and then verifying it actually happened by reading the assembly output.

## What I learned

- The AoS vs SoA benchmark was one of those "I've read about this but never measured it" moments. The performance gap was bigger than I expected, and it made cache lines feel like a real thing instead of an abstract concept.
- Reading assembly to verify auto-vectorization was intimidating at first but `godbolt.org` makes it manageable. Spotting the packed SSE instructions in the output felt like levelling up.
- Static vs dynamic libraries finally clicked once I saw the runtime dependency issue firsthand — binary runs fine on my machine, fails on another because the `.so` isn't there. Obvious in hindsight.
