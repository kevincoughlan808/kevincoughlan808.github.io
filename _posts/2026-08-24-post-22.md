Solid week — pushed through Days 83–84 of the 100 Days of Code challenge. Stayed in the design patterns lane and got into some more interesting C++ territory.

## What I built

Day 83 was Strategy and Command patterns. Strategy with swappable sort algorithms — clean way to swap behavior at runtime without touching the calling code. Command pattern with an undo stack, which was the more interesting one. Building up a history of commands and walking backwards through them felt immediately practical.

Day 84 was CRTP — static polymorphism with a Shape base and a Printable mixin. No vtable, all resolved at compile time. It's one of those C++ techniques that looks weird the first time you see a class inheriting from a template of itself, but once it clicks it clicks.

## What I learned

- Command with undo made me think about how many applications are just stacks of reversible operations. Text editors, drawing tools, even game actions — it's the same pattern everywhere.
- Strategy felt like the natural evolution of the Abstract Factory work from Day 81. Once you start thinking about swapping behavior through interfaces, a lot of design decisions get cleaner.
- CRTP is powerful but I can see why people reach for virtual functions first. The compile-time polymorphism is fast but the template syntax is a tax on readability. Worth knowing when performance matters though.
