Big week — pushed through Days 44–49 of the 100 Days of Code challenge. This stretch covered a lot of ground: hash maps, sorting, graphs, and dynamic programming.

## What I built

Day 44 was building a hash map from scratch and then comparing it against `std::unordered_map`. Day 45 was sorting — bubble sort, merge sort, quicksort, plus benchmarking them all against `std::sort`. Spoiler: `std::sort` wins, but writing the others by hand was the point.

Days 46–47 were graphs. Started with adjacency list and matrix representations, then implemented BFS, DFS, and shortest path on a weighted graph. Day 48 shifted into dynamic programming — Fibonacci, coin change, and longest common subsequence. Day 49 wrapped up with STL algorithms: `find_if`, `transform`, `accumulate`, `partition`, `count_if`.

## What I learned

- Benchmarking my sorting implementations against `std::sort` was humbling. It's one thing to know the standard library is optimized — it's another to see your quicksort get demolished and then think about why.
- Graph algorithms felt more natural in C++ than I expected. Adjacency lists with `std::vector<std::vector<std::pair<int, int>>>` are verbose but straightforward once you stop being scared of the type signature.
- Dynamic programming is still dynamic programming — the hard part is seeing the subproblem structure, not the language. Though managing 2D DP tables manually does make you miss Python's list comprehensions.
- STL algorithms on Day 49 felt like a nice bookend. After writing everything by hand, using `transform` and `accumulate` felt earned.

## Next up

- Probably hitting file I/O and serialization next — feels like a good practical shift after all the algorithmic work.
- Want to build a milestone project that pulls together graphs or DP with the STL algorithms.
